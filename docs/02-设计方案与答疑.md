# 设计方案与答疑记录

## 一、设计方案要点(讨论稿)

### 1. 总体架构

- 后端:Python + FastAPI + aiosqlite(或 SQLAlchemy 2.0 asyncio),单进程内网部署。
- 并发:SQLite 开 WAL 模式 + 全局写锁(asyncio.Lock),写串行、读并发;每行带 `version` 乐观锁字段(`WHERE id=? AND version=?`,冲突返回 409);阶段推进/回退包事务。
- 认证双通道:浏览器 Cookie Session + 个人 API Token(`Authorization: Bearer`,可吊销、可设过期;权限范围 `read` 只读 / `read-write` 读写)。重置密码、角色变更、停用后该用户现有会话全部失效。
- 时间:日期一律按服务器配置时区计算(Demo 中修正了 UTC 与本地时间混用导致的差一天问题)。
- 定时任务:asyncio 后台任务扫描 due date,不引入 Celery/APScheduler。

```
server/src/patentflow/
  app.py          # 应用工厂(同源托管前端构建产物)
  config.py       # 部署配置(patentflow.config.yaml)
  db.py           # SQLite 表结构、WAL、全局写锁事务
  deps.py         # 当前用户:Cookie 会话 / Bearer Token(只读·读写)
  identity/       # SSO 抽象:IdentityProvider 接口(当前未注册提供方)
  notify/         # Notifier 接口 + Logging / Webhook(HMAC 签名、重试)
  domain/         # 业务:权限、专利生命周期、审查轮次、延期、KPI、成员、通知分发、提醒
  api/            # REST 路由(含 /api/sysadmin 系统管理员后台)
  seed.py cli.py  # 演示数据 / 命令行 serve · seed · hash-password · set-password
```

### 2. 角色与权限

- `user.role ∈ {user, PL, GL}`;reviewer 不是行政角色,另设 `review_assignment` 表(按专利、按阶段受邀)。
- reviewer 对被邀请专利获得「只读 + 审查操作」权限,不受 visibility 限制(例外通道)。
- **共同发明人**(`patent.collaborators`):可见并可编辑各阶段内容(正常生成版本),但不能推进/回退/归档/变更可见性;由负责人/本组 PL/GL 维护。
- **专利转交**:负责人/本组 PL/GL 可把专利转交给任意在职成员;原负责人默认保留为共同发明人(可选不保留);历史署名、团队归属不变。私有专利转交后仍为私有。入口:详情页单件转交、个人中心批量转交、成员停用时的离职交接。
- **成员停用(离职)**:GL 发起;非私有专利必须逐件指定接收人才能停用;私有草案对 GL 只显示件数(不显示标题),本人可提前自助转交,未转交的在停用时转为团队可见并交给本组 PL。停用同时吊销全部 Token、撤销其未提交的 reviewer 邀请并通知发明人;停用账号不可登录、不出现在人员选择器中,可恢复。
- **成员换组**:专利留在原组(团队可见与团队 KPI 均按原组算);原组 PL 或 GL 可在详情页手动「迁移团队」。
- **Reviewer 生命周期**:发明人可撤销尚未提交意见的邀请;reviewer 可拒绝邀请(填原因,不计入门禁);提交后在本轮结束前可修改意见;每个 reviewer 有自己的审查截止日(邀请日 + GL 配置天数,默认 7 天),到期只提醒。不设回避规则(仅排除负责人本人),reviewer 身份与分数对发明人实名可见。

### 3. 可见性

- `private`:仅发明人本人;`team`:同组成员 + 本组 PL + GL;`public`:全员只读。
- **private 对 GL/PL 完全透明**:不出现在任何列表、统计、计数中,无任何痕迹可推断其存在。
- **private 锁定草案**:私有专利只能停留在 draft 阶段;**离开过草案**(含被回退回草案)后不允许再调整为私有(依据流转记录判断,前端禁选 + 后端校验双重约束)。
- **统计口径出口统一**:KPI、阶段趋势、数据导出、通知投递都只基于「非私有」专利集合;私有专利的通知只发给本人,不受 GL 事件默认接收人配置影响。
- **放宽可见性需确认**:私有→团队/公开、团队→公开前弹窗确认;收紧直接生效。

### 4. 阶段状态机

- `draft → 可专利性审查 → 专利实施 → 专利检索 → DOI 撰写`,顺序推进、可回退,回退必填原因并写入流转记录。
- 可专利性审查为门禁阶段:reviewer 对三维度(技术难度 / 非显而易见性 / 创新性,1–5 分)打分 + 文字意见。
- **审查轮次**:`patentability.round` + `pastRounds`。门禁只统计当前轮:本轮 ≥ n 人「通过」(加权达标)且本轮无打回。**打回不自动回退**,只阻断本轮门禁;发明人可在审查阶段直接修改草案/摘要,然后「发起新一轮」——上一轮归档到 pastRounds,reviewer 名单继承并重置为待审查。从草案重新推进到审查阶段时,若上一轮已有提交,也自动开启新一轮。
- **多级回退**:允许回退到任一更早阶段;被跳过阶段的数据保留,标记 `needsRecheck`,再次进入时提示复核(保存一次即清除),截止日按默认周期重算。
- **阶段截止日重算**:推进时目标阶段若无截止日、截止日已过、或属于回退后重新进入,则按默认周期重新计算(仍受周期结束日截断)。
- 实施 / 检索阶段:Markdown 自由格式,服务端渲染 + XSS sanitize。
- 每阶段独立 due date、独立页面:draft(background / class / idea)、可专利性(三维度评分 + reviewer 列表)、DOI(标题 / 作者 / 目标期刊会议 / 摘要草稿)。
- **阶段默认周期(GL 可配)**:新建/推进时按 `config.stageDefaults` 自动算出该阶段 due date,发明人可再调整。
- **审查门禁细则(GL 可配)**:通过人数 n + 加权均分下限 + 各维度显示名/权重;「通过」加权低于下限不计入门禁(提交即拦截)。

### 5. 专利归档

- 两种归档类型:`completed`(流程走完,成果沉淀)与 `abandoned`(终止推进,如新颖性不成立),归档原因必填。
- 归档后:内容只读;退出流水线与阶段趋势统计;单独进入「已归档」列表。KPI 分母规则见第 9 节。
- 归档 / 恢复归档在流转记录中使用独立的 `archive` / `unarchive` 类型(from = to),不参与 KPI「到达」判断。
- **删除**:仅负责人、且专利从未离开草案、从未邀请过 reviewer 时可物理删除(需输入编号确认);其余只能归档。
- 可由发明人 / 本组 PL / GL 恢复(原因必填),恢复后回到原阶段;归档与恢复均写流转记录并触发通知。

### 6. 数据版本控制

- 每阶段数据为 JSON 文档,存 `stage_data` 表:`(patent_id, stage, version, data_json, updated_by, updated_at, change_note)`,只追加不改历史。
- 阶段推进/回退写 `stage_transition` 记录;恢复旧版本 = 以旧内容生成新版本,历史永不丢失。

### 7. SSO 解耦

```python
class IdentityProvider(Protocol):
    name: str
    async def begin_auth(self, redirect_uri: str) -> AuthRedirect: ...
    async def complete_auth(self, callback_params: dict) -> ExternalIdentity: ...
    # ExternalIdentity = {issuer, subject, email, display_name, raw_claims}
```

- 本地账密也是 Provider 之一,地位平等;`external_identity` 表 `(issuer, subject, user_id)` 多对一绑定。
- 无通知渠道时忘记密码:由系统管理员在 `/sysadmin` 生成临时密码线下告知。
- 绑定策略可配并存:① email 自动匹配;② 首次登录后账密验证绑定;③ GL 预绑定 subject。
- 接具体 SSO(企业微信 / OIDC / CAS)= 新增一个 Provider 实现,业务代码零改动。

### 8. 通知回调

- `Notifier` 接口 `send(event)`,默认实现 Logging + Webhook(POST + 签名头 + 重试)。
- 触发点:reviewer 被邀请/提交/打回、due date 临近(默认前 3 天/前 1 天/当天)。
- 三级配置:**GL 事件默认接收人**(事件 × 发明人/本组 PL/GL)→ 专利级阶段配置(覆盖)→ **个人订阅偏好**(按事件屏蔽、due 提醒提前量、免打扰时段)。
- 每阶段通知人配置:具体用户 + 角色(本组 PL)+ 专利相关人(发明人),JSON 存储。

### 9. KPI 管理

- 规则 JSON:名称、范围(team/global)、基准起始日、目标节点列表(阶段 × 截止日)、scorerHook(可选)。
- **到达事件**:只认 `advance` 类流转,且取该专利**首次**到达(≥)目标阶段的时间;回退、归档、恢复归档都不算。某阶段在往期周期首次到达后,本周期回退再推进不重复计。
- **分母**:周期内活跃的非私有专利;完成归档保留;放弃归档仅当放弃日早于周期结束前 N 天(GL 配置,默认 30)才退出分母——防止收口前突击放弃刷分。
- **计分方式**(`rule.scoring`):`ratio` 按比例(单件 = 达成目标数/目标总数,整体取均值);`tiered` 分段阈值(按「全部目标均达成」的件数落档,如 ≥8 件 100%、≥5 件 60%,否则 elseScore)。UI 可视化配置;`scorerHook` 非空时改走自定义回调。
- **我的贡献**:所有用户在 KPI 页可看到自己(负责人/共同发明人)计入 KPI 的专利、每件已达成几个节点、下一个节点及截止日。普通用户不能建规则。
- 规则可**停用/启用**(停用的不进仪表盘,历史保留),记录 updatedAt。
