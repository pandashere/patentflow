# 设计方案与答疑记录

## 一、设计方案要点(讨论稿)

### 1. 总体架构

- 后端:Python + FastAPI + aiosqlite(或 SQLAlchemy 2.0 asyncio),单进程内网部署。
- 并发:SQLite 开 WAL 模式 + 全局写锁(asyncio.Lock),写串行、读并发;每行带 `version` 乐观锁字段(`WHERE id=? AND version=?`,冲突返回 409);阶段推进/回退包事务。
- 认证双通道:浏览器 Cookie Session + 个人 API Token(`Authorization: Bearer`,可吊销、可设过期)。
- 定时任务:asyncio 后台任务扫描 due date,不引入 Celery/APScheduler。

```
app/
  api/          # 路由层(patents, stages, users, kpi, tokens...)
  core/         # 权限、状态机、版本控制
  identity/     # SSO 抽象:IdentityProvider 接口 + local 实现
  notify/       # Notifier 接口 + webhook/logging 实现
  kpi/          # KPI 规则引擎
  models/       # SQLAlchemy 模型
  ui/           # 静态 SPA(构建产物)
```

### 2. 角色与权限

- `user.role ∈ {user, PL, GL}`;reviewer 不是行政角色,另设 `review_assignment` 表(按专利、按阶段受邀)。
- reviewer 对被邀请专利获得「只读 + 审查操作」权限,不受 visibility 限制(例外通道)。
- **共同发明人**(`patent.collaborators`):可见并可编辑各阶段内容(正常生成版本),但不能推进/回退/归档/变更可见性;由负责人/本组 PL/GL 维护。
- **负责人变更**:负责人/本组 PL/GL 可转让(离职交接场景),原负责人自动转为共同发明人,历史署名不变。

### 3. 可见性

- `private`:仅发明人本人;`team`:同组成员 + 本组 PL + GL;`public`:全员只读。
- **private 对 GL/PL 完全透明**:不出现在任何列表、统计、计数中,无任何痕迹可推断其存在。
- **private 锁定草案**:私有专利只能停留在 draft 阶段;离开草案后不允许再调整为私有(前端禁选 + 后端状态机校验双重约束)。

### 4. 阶段状态机

- `draft → 可专利性审查 → 专利实施 → 专利检索 → DOI 撰写`,顺序推进、可回退,回退必填原因并写入流转记录。
- 可专利性审查为门禁阶段:reviewer 对三维度(技术难度 / 非显而易见性 / 创新性,1–5 分)打分 + 文字意见;任一打回自动回退草案。
- 实施 / 检索阶段:Markdown 自由格式,服务端渲染 + XSS sanitize。
- 每阶段独立 due date、独立页面:draft(background / class / idea)、可专利性(三维度评分 + reviewer 列表)、DOI(标题 / 作者 / 目标期刊会议 / 摘要草稿)。
- **阶段默认周期(GL 可配)**:新建/推进时按 `config.stageDefaults` 自动算出该阶段 due date,发明人可再调整。
- **审查门禁细则(GL 可配)**:通过人数 n + 加权均分下限 + 各维度显示名/权重;「通过」加权低于下限不计入门禁(提交即拦截)。

### 5. 专利归档

- 两种归档类型:`completed`(流程走完,成果沉淀)与 `abandoned`(终止推进,如新颖性不成立),归档原因必填。
- 归档后:内容只读;退出流水线、阶段趋势统计与 KPI 基准集;单独进入「已归档」列表。
- 可由发明人 / 本组 PL / GL 恢复(原因必填),恢复后回到原阶段;归档与恢复均写流转记录并触发通知。

### 6. 数据版本控制

- 每阶段数据为 JSON 文档,存 `stage_data` 表:`(patent_id, stage, version, data_json, updated_by, updated_at, change_note)`,只追加不改历史。
- 阶段推进/回退写 `stage_transition` 记录;恢复旧版本 = 以旧内容生成新版本,历史永不丢失。

### 7. SSO 解耦

```python
class IdentityProvider(Protocol):
    name: str
    async def begin_auth(self, redirect_uri: str) -> AuthRedirect: ...
    async def complete_auth(self, callback_params: dict) -> ExternalIdentity: ...
    # ExternalIdentity = {issuer, subject, email, display_name, raw_claims}
```

- 本地账密也是 Provider 之一,地位平等;`external_identity` 表 `(issuer, subject, user_id)` 多对一绑定。
- 绑定策略可配并存:① email 自动匹配;② 首次登录后账密验证绑定;③ GL 预绑定 subject。
- 接具体 SSO(企业微信 / OIDC / CAS)= 新增一个 Provider 实现,业务代码零改动。

### 8. 通知回调

- `Notifier` 接口 `send(event)`,默认实现 Logging + Webhook(POST + 签名头 + 重试)。
- 触发点:reviewer 被邀请/提交/打回、due date 临近(默认前 3 天/前 1 天/当天)。
- 三级配置:**GL 事件默认接收人**(事件 × 发明人/本组 PL/GL)→ 专利级阶段配置(覆盖)→ **个人订阅偏好**(按事件屏蔽、due 提醒提前量、免打扰时段)。
- 每阶段通知人配置:具体用户 + 角色(本组 PL)+ 专利相关人(发明人),JSON 存储。

### 9. KPI 管理

- 规则 JSON:名称、范围(team/global)、基准起始日、目标节点列表(阶段 × 截止日)、scorerHook(可选)。
- 引擎按 `stage_transition` 判断「到达过」目标阶段(不受后续回退影响),默认得分 = 达成目标数 / 目标总数。
- 规则可**停用/启用**(停用的不进仪表盘,历史保留),记录 updatedAt。

### 10. API 概览(Bearer Token)

```
POST   /auth/login
GET    /auth/sso/{provider}/begin | /callback
GET|POST /users, /users/{id}/identities
GET|POST /patents
GET|PATCH /patents/{id}/stages/{stage}     # PATCH 带 version 乐观锁
POST   /patents/{id}/stages/{stage}/advance|rollback
GET    /patents/{id}/stages/{stage}/versions
POST   /patents/{id}/reviews
POST   /patents/{id}/archive | /unarchive
POST   /patents/{id}/transfer             # 负责人变更
PUT    /patents/{id}/collaborators        # 共同发明人
GET|POST /users, PATCH /users/{id}        # GL 成员管理(角色/团队)
GET|POST /tokens, DELETE /tokens/{id}     # 个人 Token;GL 可吊销任意
GET|PUT  /me, /me/prefs                   # 个人资料与通知偏好
GET    /export.json | /export/patents.csv # 数据导出
GET    /stats/stage-trend?months=N          # GL/PL 时间×阶段数折线统计
GET|PUT  /patents/{id}/notification-settings
GET|POST /kpi/rules, GET /kpi/rules/{id}/report
GET|POST /tokens
```

## 二、答疑记录(用户决策)

| # | 问题 | 决策 |
|---|------|------|
| 1 | GL 是否可强制查看 private 专利? | **不可见**,private 仅发明人本人可见 |
| 2 | 邀请 reviewer 是否需要 PL 审批? | **不需要**,发明人直接邀请 |
| 3 | 审查通过标准? | **至少 n 名 reviewer 通过,n 由 GL 全局配置** |
| 4 | class(分类)字段形态? | **自由文本** |
| 5 | 专利检索阶段结构? | **先自由格式(Markdown)** |
| 6 | KPI 基准集与计分? | **预留自由计算回调接口(单项目 compute_item / 整体 compute_kpi),暂且按比例给分** |
| 7 | 通知事件范围? | **除 reviewer / due date 外,阶段推进、回退、打回也预留** |
| 8 | UI demo 形态? | **React SPA 高保真可交互 demo(纯前端 mock 数据,角色可切换)** |
| 9 | private 对 GL/PL 的隐藏程度? | **完全透明:无任何列表项、计数或统计痕迹** |
| 10 | private 专利的阶段限制? | **只能停留在 draft;离开草案后不可再设为私有** |
| 11 | 专利终止/完成后如何处理? | **归档(完成/放弃两类),只读、退出流水线与 KPI,可恢复** |
| 12 | GL/PL 的宏观统计? | **仪表盘提供「时间 × 各阶段专利数」折线图(GL 全量 / PL 本组,均不含归档与无权可见专利)** |
| 13 | GL 可配置什么? | **审查门禁(n + 加权下限 + 维度名/权重)、阶段默认周期、通知默认接收人、编号前缀与 class 词表、成员与角色、KPI 启停、Token 全局吊销、数据导出;不做超期升级,SSO 维持现状** |
| 14 | 普通用户可修改什么? | **个人资料/密码、API Token(创建/吊销/有效期)、通知订阅偏好与免打扰、新建默认可见性与着陆页** |
| 15 | 多人合著如何表达? | **共同发明人:可编辑不可操作;负责人变更后原负责人自动转为共同发明人** |
| 16 | 「通过」的分数质量如何约束? | **GL 设加权均分下限,低于下限的「通过」提交时被拦截** |
| 17 | class 自由文本如何引导规范? | **GL 维护建议词表,输入联想但不强制** |

| 18 | 专利周期是什么、归谁定? | **项目级时间窗口,GL 定义起止与收口;任何人自定的阶段周期/KPI 截止日都必须落在周期内(超出自动截断)** |
| 19 | 专利归属哪个周期? | **按创建日落入周期(多个进行时取最早开始者);周期收口后未完成专利转入逾期管理,或由 GL 标记「跨周期」豁免** |
| 20 | KPI 与跨周期如何解耦? | **事件口径:统计周期窗口内「到达过目标阶段」的流转事件,与专利创建时间无关;跨周期项目各记各的、无双计;是否计入由 GL 开关控制** |
| 21 | 周期收口时 KPI 怎么办? | **收口瞬间冻结为 KpiSnapshot,之后不再随后续流转变化** |
| 22 | 逾期怎么管? | **阶段逾期纯派生(当前阶段 due 与今天之差);Dashboard 分桶看板(1–7/8–14/15+);收口风险三档(剩余周期天数 vs 剩余阶段默认预算);手动催办,不做自动升级** |
| 23 | 延期怎么走? | **分级审批:单次 ≤ GL 阈值(默认 14 天)自动生效,超过挂起待本组 PL/GL 批准;不可超出所属周期结束日(跨周期项目除外)** |
| 24 | 周期内放弃归档的专利影响 KPI 吗? | **不拖累:放弃归档退出分母;完成归档保留(周期内的进展仍是产出)** |

| 25 | 第一个 admin 从哪来? | **配置文件(patentflow.config.yaml)的 admins 邮箱列表引导:启动时保底为 GL;配置文件管理员受保护,UI/API 不可降级,变更只能改配置重启 —— 这是防锁死的恢复通道** |
| 26 | 权限在哪强制? | **后端唯一权威:每个写接口以 FastAPI 依赖注入重做角色校验(能力见 Admin 页权限矩阵);前端隐藏按钮只是体验层。角色维持 user/pl/gl + reviewer 按专利邀请,不引入 ACL** |
| 27 | 忘记密码怎么办? | **经既有通知接口(webhook 回调 → 邮件/IM 适配器)投递带一次性 token 的重置链接:30 分钟有效、用后作废;无论账号是否存在都返回相同话术(防枚举);账号安全事件强制送达,不受个人订阅与免打扰影响** |
