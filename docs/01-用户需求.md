# 用户需求(原始)

> 我需要做这样一个专利管理系统——只做简单的状态跟踪功能,内网运行。具体要求包括:
>
> 1. **租户管理**:普通用户 / PL / GL 三级权限,额外包含 reviewer。
> 2. **可见性**:专利可以 private / team 可见 / public,team 可见下对应 PL/GL 也可见。
> 3. **专利阶段**:draft → 可专利性审查 → 专利实施 → 专利检索 → DOI 撰写。其中第二阶段需要可以邀请 reviewer 审查,审查通过才可以完成实施。
> 4. **SSO**:租户管理需要预留 SSO 登录空间接入接口(之后可以根据具体 SSO 写接入层,重点是接口解耦。如何绑定本地租户及 SSO 也需要考虑)。
> 5. **通知回调**:留用户回调能力(发通知用),用户可以配置各个阶段的通知发给谁。需要发通知的情况——reviewer 审查、due date 提醒。每一阶段用户可以通过 setting 设置通知人(通知只需要留回调接口,通知 callback 以后实现)。
> 6. **回退与版本**:各阶段要可回退,要有数据版本控制。
> 7. **阶段页面**:每个阶段要有自己的页面。draft 需要 background、class、idea;可专利性包括三维度——技术难度、非显而易见性、创新性;实施阶段暂且不设,直接解析用户 Markdown。每一阶段设置 due date。
> 8. **KPI 管理**:用户侧也有 KPI 管理——从 xxx 日起,多少专利在 yyy/zzz 日之前达到 aaa/bbb 状态,则 KPI 达成 i%,否则为……(KPI 管理要足够易配置)。
> 9. **技术约束**:轻量化服务,小规模并发安全,无依赖重型服务,SQLite 或 async SQLite,几十人团队使用。界面足够美观,针对不同权限的界面要有考虑,重视用户 UI 体验。有用户 token,给出数据更新和获取 API,凭 token 调用。
>
> 现在只做设计和 UI demo,可以先讨论细化。
