# 代码审核记录(Codex review → 筛选 → 修复)

审核者:Codex(gpt-6.2-astra,只读沙箱);筛选与修复:Claude。
审核边界:`main..HEAD` 的后端 `server/` 与前端 `src/`;任务类型为缺陷审核(权限/可见性、业务规则实现、数据一致性、认证会话、前后端契约)。
不在范围:风格、性能(数据量百级)、多实例/分布式、SSO(决策留空)、限流/安全头、对已确认产品决策的不同意见。
筛选原则:按「几十人内网单进程服务」的尺度,只修复有现实触发场景、会造成错误行为或违背决策的问题。

## 第 1 轮(12 条:修复 10,驳回 2)

| # | 问题 | 处理 |
|---|---|---|
| 1 | 生产托管前端时 SPA 回退路由可路径穿越读取发布目录外文件 | 修复:解析真实路径并限制在发布目录内 |
| 2 | 重置/激活链接写入站内通知,只读 Token 可读到并改密提权 | 修复:一次性链接只走外部渠道,站内仅提示 |
| 3 | 管理员被降级的毫秒级窗口内,其排队中的写请求仍按旧权限执行 | 驳回:单进程内网、需两名管理员同一事务窗口内操作,理论风险 |
| 4 | 同一重置链接并发提交两次 | 驳回:后果仅为同一用户密码被设置两次,无安全影响 |
| 5 | 收口快照含后来改回私有的草案,GL 仍可见明细 | 修复:输出时按当前可见性剔除(决策 9) |
| 6 | 草案改回私有后,GL/PL 历史通知仍返回标题 | 修复:通知按关联专利当前可见性过滤 |
| 7 | 被撤销邀请的外组 reviewer 凭往轮记录仍可读专利 | 修复:例外通道只认当前轮未拒绝的邀请 |
| 8 | 从后续阶段回退到审查,沿用已结束轮次的通过票直接放行 | 修复:回退进入审查时开启新一轮 |
| 9 | 转交给本轮 reviewer 后,新负责人可给自己投票 | 修复:门禁与提交均排除当前负责人,新轮不继承 |
| 10 | 离职交接把私有草案交给按 id 排序的首个 PL 而非现任 PL | 修复:以 teams.pl_id 为准 |
| 11 | 两人各点一次推进,专利连跳两个阶段 | 修复:前端携带 rev,后端乐观锁返回 409 |
| 12 | 收口使用写锁外读取的数据,可能漏记刚提交的进展 | 修复:在同一写事务内读取 |
